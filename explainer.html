Eventual Consistency in 60 Seconds

Text companion

When you save a post, a big app copies it to several servers. Those copies don't all update at the same instant, so for a moment one server can still show the old version. Eventual consistency means that if no new changes arrive, every copy ends up the same.

Think of a group chat on a bad connection: your friends' phones get your message at slightly different times, but once everyone syncs, everyone sees the same thread.

Common misconception: "eventual" doesn't mean data gets lost. The write is kept; some readers just see it a little late. Apps choose this because it keeps working when servers can't reach each other, at the cost of short-lived stale reads.

Where the analogy breaks: a chat shows messages in order, but replicas can receive updates in different orders, so real systems need rules (like last-writer-wins or merging) to agree on one final value.
