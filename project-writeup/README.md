# project-writeup

A skill that turns a finished project into a short, honest portfolio write-up.

I wrote it after sharing about fifty projects to a profile in one sitting. The
job repeats: read the project, answer the platform's questions, stay under 500
characters.

## Example

**Input:** the Exam Season Jar page (`gift.html` in this repo) and the prompt
"What did you make, who is it for, and what does it do?"

**Output:**

> **Exam Season Jar: An App Made as a Gift**
>
> A gift for a friend going into exam season: a jar of notes, one to open each
> day until the last exam. Tap the jar and it draws a random note that hasn't
> been opened yet. It remembers which notes are opened on that phone and counts
> how many are left, and the "Last one" note is always saved for the end. It's
> one link, with no account or install.

## What changed after testing

Early drafts added details that sounded right but were not in the project, such
as a feature the page did not have or a result nobody measured. Step 4 (check
every sentence against the visible facts) was added because of that. The jar
example is also why the app changed: the first draft claimed the last note was
saved for the end, the code did not do that, so I fixed the code.
